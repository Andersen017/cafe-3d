# Обновление модели

Ссылка GitHub Pages постоянная. Новая версия заменяет публичную модель в том же репозитории.

1. Проверить действующую редакцию нового раздела и его соответствие текущему АР. Существенные расхождения зафиксировать до изменения геометрии.
2. Обновить `model/canonical.json`. Сохранять существующие `id`; новые элементы получают новые идентификаторы. Единицы — метры; координаты совпадают с паспортом модели.
3. Для нового раздела добавить запись в `sources` и отдельный слой в `layers`. Имя группы задаёт раздел панели. Электрические кабели добавляются в ЭМ, вода — в водоснабжение, стоки — в водоотведение; существующие точки подключения остаются в соответствующих разделах.
4. Для элемента задавать `layer`, `sources`, `status`, `properties` и `geometry`. Типы геометрии: `box`, `prism`, `opening`, `equipment`, `beam`, `marker`. Материал выбирается из `materials`.
5. Уточнённые решения заменяют условные габариты и отделку. Назначение фактического пирога ограждения требует отдельного элемента для каждого подтверждённого материала; поверхностные слои первой версии заменяются согласованными решениями.
6. Обновить `revision`, `date`, открытые вопросы и ограничения; выполнить `pnpm build` и `pnpm validate`.
7. Проверить обзор, план, срез, карточки, независимые слои и прогулку на обычной и узкой ширине окна. Изменение размеров мебели / стен требует обновления физических препятствий в `walk.obstacles`.
8. Перед публикацией проверить перечень файлов: исходные DWG/PDF, внутренние документы, выгрузки, личные данные и локальные пути в Git не попадают. Коммит включает только согласованные публичные файлы, новую модель GLB и описание.

Выполняется совместная актуализация проектной командой. Посетители страницы осматривают модель; редактирование и измерения в клиентском просмотрщике не предусмотрены.
